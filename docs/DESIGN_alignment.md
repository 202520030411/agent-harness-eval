# 题面—验收对齐层（Spec–Grader Alignment）设计（2026-09-25，第三圈蓝图）

## 问题
失败归因里最大的一类不是“做不出”，而是“做出来的东西和看不见的验收方对不上”：人工核实 24 条里题面缺信息 8、验证不足 6、超时无交付 4，合计 75%。验收方看不见，但它是出题人照题面写的，可以建模。

## 核心思想
harness 显式维护一份**契约对象**：“我认为验收方会查什么”。每条带来源（stated：题面字面 / inferred：环境证据推出 / assumed：模糊点的选择）和状态（open / resolved），先变成可执行的检查，再在交付前逐条对账。契约对象写进 trial 元数据，评测流水线据此算每段指标。

## 五段流水线

| 段 | 输入 → 输出 | 现有实现 | 指标 |
|---|---|---|---|
| S1 提取 | 题面 → 字面要求、交付文件路径、点名场景、模糊点（七类清单：单位换算、地址/基址、重复序列边界、名字签名字面、验收进程环境、范围词、工具版本） | `task_contract`（v1/v2）、`extract_deliverables` | 决定性细节覆盖率（契约臂 63% → 目标 80%） |
| S2 探查 | 模糊点 → 环境证据（预装工具、文件格式、账号、端口） | v2 第二轮必须跑 `evidence_to_check` | 探查执行率 |
| S3 决策 | 证据 → 每个模糊点的读法 + 来源；优先级：字面/示例 → 对所有读法成立 → 更严格更通用 → 参考实现默认 | v2 `resolutions` | 读法正确率（事后对照隐藏测试） |
| S4 落成检查 | 契约 → 可执行自检（自写 grader）：重放题面原话命令、新进程验、交付物存在与格式、场景变体 | `grader_check`（提醒版，待升级为代码版） | 自写 grader 与真 grader 一致率；作为 best-of-k 选择器的准确率（H14） |
| S5 对账交付 | 跑 S4；逐条对账模糊点；到时先写交付物 | `deliverable_checkpoint`、v2 收尾对账 | 超时无交付率；自检假阳性率 |

## 横切规则
1. 来源红线：只用题面、容器内容、benchmark 公开惯例（TB：pytest、新子进程、root、/app、字面路径、数值容差、apt 默认版本）。访问 /tests、/logs、参考解记 INTEGRITY_SUSPECT。
2. 预算：S1–S3 合计 ≤ 2 轮；S4 检查在完成前一次跑完；每段的额外轮数计入成本表。
3. 可观测：契约对象与每段执行统计写入 `context.metadata["patched"]`，指标离线可算，不依赖判官。
4. 通用性：清单和规则必须跨题通用（来自审计的缺陷类型），禁止针对单题的提示。

## 与失败分类的对应
- 题面缺信息但可推导 → S1–S3；不可推导（示例自相矛盾、测试契约与题面矛盾）→ 审计，不属 harness。
- 验证不足 / 自测不像验收 → S4。
- 超时无交付 → S5。
- 能力、领域知识 → 模型侧或工具（看图、多跑几次再选）。

## 闭环
审计（缺陷类型）→ S1 清单；人工标注 → 校准判官 → 算每段指标 → 决定下一段改哪。第一圈：按判官分布改；第二圈：按人工修正的 bp 改（检查点、验收式清单）；第三圈：按对齐层分段改（v2 = S1–S3，自写 grader = S4）。

## 实验顺序
E4p（跑中）：v2 对 v1，看 S1–S3 是否把模糊题子集再抬起来、覆盖率是否到 80%。有效 → 做 S4 代码版；同时用 39 条失败的隐藏测试离线算“自写 grader vs 真 grader 一致率”作为 S4 的基线。

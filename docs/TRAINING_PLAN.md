## 0. 一句话

评测流水线把失败分三路：题目缺陷（证据不在环境里）→ 提 issue 修题（已做）；harness 缺陷 → 改 harness（自适应等待）；**模型不会去找环境里已有的证据 → 训练（本计划）**。按实习时的造题思路合成“题面缺约定、环境里有证据”的任务，拒绝采样 + LoRA SFT，回到同一条评测流水线验证：合成留出题、未见过的类别、多文件真实感项目，以及 TB 2.1 干净题上不退化；最后检验训练后 harness 的契约是否变成多余。

## 1. 训练什么行为，为什么是它

| 来源 | 证据 |
|---|---|
| 契约实验（D-048/D-050） | 模型列出的模糊点 80% 命中决定性细节；强制它逐点做决定后，命中时的通过率从 8/12 掉到 3/12 |
| harness 侧结论（D-047） | 提示模型“多查一步”在 15 分钟时限下是负项，三种验证类改动都不提分 |

目标行为（可判定）：**题面没写清某个影响验收的约定、而环境里有给出该约定的文件时，提交前读到它并按它做；题面写清时不多读。**

**适用范围只限“证据在环境里”。** 按人工判定规则（D-041 的可推导性测试），“只凭题面 + 容器推不出决定性细节”的失败记为题目缺陷，不是模型问题，本计划不针对它们，见第 2.4 节。

## 1.4 阶段 0（2026-09-27 再修订，取代下面“先预设目标行为”的做法）：训练目标从学生自己的失败里找

**原则：** 训练什么由学生（Qwen3-Coder-30B-A3B）自己的失败决定，不沿用从 Seed 推出来的毛病；第 1 节和 §1.5 的“查证据”降为候选假设之一，只有在 Qwen 的失败里确实占比够高才会被选中。流程与实习时一致：对比强弱模型轨迹，提炼弱模型的 bad pattern，再针对它造题。

| 步骤 | 做法 | 工具 |
|---|---|---|
| 1. 跑 | Qwen3-Coder-30B-A3B（OpenRouter）在 TB 2.1 审计后干净的 30 道 × 3 次，Terminus 2，同之前所有 TB 实验；只用干净题，失败里就不混题目缺陷 | `experiments/configs/stage0-qwen-coder30b-tb21clean.resolved.yaml`（改 k=3） |
| 2. 标 | 规则标签（免费）+ 两家 v3 判官全上下文各 1 票取共识；分歧的我抽查 | `agenteval analyze` / `agenteval judge --prompt attribution_v3.txt --full-context` |
| 3. 归责 | 2×2：同一批题上对照 gpt-6-sol（E2、E4s 已有轨迹）与 Seed | `agenteval blame` |
| 4. 出表 | Qwen 的 bad pattern 表：频率、归责、3–5 条代表轨迹、已知的 harness 侧缓解 | 同 `reports/e4/handoff_model_patterns.md` 的格式 |

**选目标的标准（看到 Qwen 数据之前写死）：**
1. 归责为 MODEL 或 MIXED：Qwen 的发生率比 gpt-6-sol 高至少 δ = 8 pp（同一批题）；
2. 占 Qwen 失败的 ≥ 15%；
3. 能造成“结果可验证”的任务：有这个毛病就过不了、改掉就能过，判分是脚本；
4. 这周训得完：能在进程内环境或 ≤10 分钟的 Harbor 任务里采样；
5. 同分时优先：Seed 也有的（更普遍），以及和 TB 时限直接相关的（多走轮次、预算耗尽）。

最多选 2 个。都不满足 → 停掉训练线。

**造题（第 2 节）随之改为以选中的 bad pattern 为条件：** 提案时附上 Qwen 在这个毛病上的代表轨迹；Verifier 加一道门：Qwen 原版在这道题上确实因为这个毛病失败（看轨迹），而强模型能过。

**规模与花费：** 90 次试验，Qwen 预计通过 25–60% → 约 35–65 条失败；OpenRouter 约 3 美元；判官两家各 1 票约 10–15 美元（OpenAI 与 Anthropic 现有余额够）。时间：跑 2–3 小时，归因约 1 小时。

### 阶段 0 结果（2026-09-26 晚，美东；`reports/stage0/`）

Qwen3-Coder-30B-A3B（OpenRouter，Alibaba 官方服务商）在 TB 2.1 干净题 30 道 × 3 次：**18/90 = 20%**（Seed 81%，gpt-6-sol 91%），花费 18.7 美元。服务商坑：Novita 同一提示 6 次里 5 次返回空内容，已排除（见 D-052）。

规则统计（`tools/stage0_patterns.py`，三个模型同一口径）：

| 毛病 | Qwen | Seed | gpt-6-sol |
|---|---|---|---|
| 用 echo 打印代替检查（失败 trial） | 51% | 0% | 0% |
| JSON 控制字符错误（全部 trial；平均每 trial 浪费 4.9 轮） | 50% | 1% | 0% |
| 明知没做成仍宣布完成（失败 trial） | 26% | 3% | 1/6 |
| 格式错误卡死到结束 | 3% | 0% | 0% |

覆盖面：假检查 / 假成功覆盖 Qwen 失败的 46/72（64%）；JSON 错误出现在失败的 57%、通过的 22%。人工读 10 条失败：6 条“明知没做成仍宣布成功”，其中 2 条直接**编造**了答案（vulnerable-secret 写了编的 FLAG、git-leak-recovery 写了编的 secret）；query-optimize 的核心要求是“更快”，从头到尾没测过耗时。两家判官共识只有 21%（gpt 多判“验证不足”、Claude 多判“读错题”），选目标以规则统计为准。

**选中的目标（按上面写死的 5 条标准，两项都满足 1–4）：**
1. **假检查 / 假成功**（主目标）：交卷前用 echo 打印“✓ 完成”代替真正运行检查；检查失败或自己承认没做成仍宣布完成；甚至编造交付物。训练目标行为：交卷前运行能真正证明要求达成的检查；检查失败就继续修，而不是宣布完成。
2. **JSON 格式**（次目标）：在 JSON 字符串里直接换行导致解析失败、反复重试。所有 SFT 数据都来自格式正确的轨迹，这个目标随主目标的数据一起训；机制指标是每 trial 的解析错误轮数。

未选：原先由 Seed 推出来的“查证据”在 Qwen 的失败里不是主要问题，§1.5 的探针不再作为训练依据。

## 1.5 候选假设“查证据”的探针（开测前写死判定，2026-09-27）

这个毛病是从 Seed 在 TB 上推出来的，而 Seed 在证据确实存在的合成题上 95–97% 都会去查、通过率 93–96%，所以“学生有缺口”这个前提必须先测，再决定是否搭造题流水线、租卡。

| 测什么 | 谁 | 怎么测 |
|---|---|---|
| 进程内留出集 A（60 道，含 25% 清晰题），易版 + 难版（同种子配对：难版把证据放中性路径、无关文件 8 个），每题 2 次 | Qwen3-Coder-30B-A3B、Qwen3.6-35B-A3B（OpenRouter），参照 Seed lite | 缺约定题的通过率、提交前读证据的比例；清晰题的多读比例 |
| TB 2.1 审计后干净子集（30 道，`experiments/task_list_tb21_clean.txt`）× 1 次，Terminus 2 | 两个 Qwen 候选 | 基线落在哪 |

判定：
- **有可训练的缺口**：某个难度下，学生在缺约定题上通过率 ≤ 70% 且读证据率 ≤ 70%，同时 Seed 在同一批题上 ≥ 85%（老师做得到 → 可学、有数据）。
- **TB 干净子集基线**在 5–70% 之间（干净题比全集容易，上限放宽到 70%）。
- 两个候选都满足时选缺口更大的；相近时选 Coder-30B（纯文本，配置风险低）。
- 只在难版有缺口 → 训练题以难版为主，第二层 LLM 造题专做“证据不显眼”的题。
- 两个难度都没有缺口 → 停掉这条训练线，不租卡、不搭造题流水线。

说明：OpenRouter 上的服务商与精度不受我们控制，这一步只用来做继续 / 停止的判断；训练前后的正式对比都在我们自己的 vLLM（bf16）上做。

**阶段 0 修订（2026-09-27，用 Seed 做环境自检之后、测任何 Qwen 之前）：**

1. **环境加 `search` 动作（全文件关键词搜索，等价 `grep -rin`），轮数上限 10 → 15。** 原因：难版上 Seed 的 37 次失败里 35 次是 10 轮用完，它一直在找，只是只能逐个列目录、读文件；这是环境缺一个真实 shell 里人人都用的工具造成的假缺口。修后 Seed 难版缺约定题通过 20% → 78%，看到证据 43% → 93%。
2. **“看到证据”包括搜索结果里出现证据文件的行**（有了 search，光看命中行也能拿到约定）；新增效率指标：第一次看到证据的轮次（中位数）、轮数用完的比例、每题搜索次数。
3. **老师门槛 85% → 70%。** Seed 在修好的难版上 78%，低于原门槛。原门槛的用意是“老师成功轨迹够多、可做热身数据”；训练数据以学生自采为主（§2.5），70% 已足够。此修订在看到 Seed 数字之后、看到任何 Qwen 数字之前做出，记录在此。
4. **新增一个预注册的可训练缺口：“找证据太低效”。** Seed 修好后的难版：失败主要是 7 次轮数用完（46 次里只用了 17 次搜索，列目录 / 读文件 476 次，找到后还要再核对）；真正没查就答只有 3/46。所以学生可能呈现两种缺口：(a) 不去看（看到证据率 ≤ 70%）；(b) 看了但低效（轮数用完 ≥ 20%，或第一次看到证据的轮次中位数 ≥ Seed 的 2 倍）。两种都算可训练；(b) 用“同题留最短的成功轨迹”来训，并和 TB 上 15 分钟时限下“多走一轮就是负项”（D-047）直接相关。
5. 阶段 0 的正式参照数：Seed 与两个 Qwen 候选用同一版代码、同一批题**同时**跑，不复用修订前的 Seed 数字。

### 2.2 第二层：LLM 造题（实习流水线的思路，代码全部重写，不用公司代码和数据）

```
坏模式（第 1 节）+ 随机领域（日志分析 / 报表 / 数据清洗 / 配置迁移 / CLI 小工具 …）
   │
   ▼
Proposal Writer（gpt-6-sol）：一个多文件小项目（5–20 个文件，带 pytest / Makefile / 配置 / README），
   一个任务，一个故意不写进题面的约定，约定出现在哪（已有测试、已有代码的用法、配置、fixture），
   唯一正确结果，以及“不查证据时最可能的错误结果”
   │
   ▼
Task Builder（脚本）：落成 Harbor 任务（Docker）+ 判分器；能落成单文件工作区的同时导出进程内格式
   │
   ▼
Task Verifier（四道门，任一不过就丢）
   1. oracle：参考解能通过判分器
   2. 遮蔽红队：删掉证据后老师做 3 次仍能过 → 约定不是决定性的（题面泄露或可猜），丢
   3. 难度门：有证据时老师 3 次至少过 1 次
   4. 盲评判官：题面自然、不暗示“去找配置”；证据要能通过正常工程动作找到（读测试、grep 用法、看配置）
```

目标：提案 800 → 过门约 400–500。

### 2.4 为什么不在 TB 2.1 的“模糊题”上测迁移

这 14 道题（clarity ≥2）按审计分类，没有一道是“证据在容器里、模型没去看”：

| 类别 | 题 |
|---|---|
| 决定性细节只在隐藏测试里（已提 issue 或社区已报） | cancel-async-tasks #238、sanitize-git-repo #239、extract-elf #194、dna-insert #100、raman-fitting PR #1、count-dataset-tokens PR #2、pytorch-model-cli PR #6 |
| 答案泄露 | fix-code-vulnerability #134 |
| 能力或验证问题 | chess-best-move、headless-terminal、adaptive-rejection-sampler |
| 弱模型本来就全过 | build-pmars、fix-git、vulnerable-secret |

在它们上面，训练的预期效应按构造就是 0；若上涨，只能来自猜中判分器或抄到残留答案，属于坏信号。它们也是我们自己报告为“坏题”的题，不当训练目标。D 组因此只用审计后干净的题，缺陷题（上表 7 道 + fix-code-vulnerability + configure-git-webserver、largest-eigenval、git-multibranch）全部剔除。

### 2.5 训练样本：拒绝采样，优先用学生自己的轨迹，格式与评测对齐

> **2026-09-26 更新（不蒸馏，见 `QWEN_PLAN.md` §4）：** 训练数据只用学生自己的 rollout；老师（Seed）轨迹不再作为热身数据，已采的 1256 条作废。别的模型只负责出题、给提示（训练时删掉）、写 rubric、判分。

- **学生自采（主）：** 学生在训练题上每题 4 条，只留“通过 + 提交前读过证据 + 无格式错误”；同题多条通过留最短的，压住“翻遍所有文件”。清晰题只留“通过且没多读”。
- **老师轨迹（热身）：** 学生基线在缺约定题上 <20% 时先用老师数据训一轮，再用学生自采数据训第二轮；≥20% 时不用老师数据。
- **格式对齐：** 训练数据约一半直接在 **Terminus 2 + Docker** 里采（老师 Seed 跑第二层的 Harbor 任务），另一半来自进程内 JSON 环境（量大、快）。否则 C / D 组上的零结果分不清是“没学会”还是“只在 JSON 工具格式里学会了”。

## 3. 训练方法

| 阶段 | 方法 | 何时做 |
|---|---|---|
| 1 | LoRA SFT（只加注意力层，rank 16，学习率 1e-4，2 个 epoch，只对助手轮算 loss） | 必做 |
| 2 | 第二轮拒绝采样：用阶段 1 的模型再采、再筛、再训 | 阶段 1 在 A 上有效且时间允许 |
| 3 | GRPO：只用结果奖励、每题 8 条、KL 系数 0.02 | 可选；仅当 A/B 有提升而 C 没有时做 |

不用过程奖励（“读了配置就加分”）：会学成走过场；任务保证不查就过不了，结果奖励足够。

## 4. 判定口径（训练前写死）

| 指标 | 成立的条件 |
|---|---|
| A 通过率 | ≥ 基线 + 15 pp，bootstrap 95% 区间不含 0 |
| **C 通过率（主要）** | **≥ 基线 + 10 pp，区间不含 0** |
| B 通过率 | 方向与 A 一致 |
| 机制指标 | 缺约定题里“提交前读过证据”的比例上升；清晰题里“多读无关文件”的比例不上升 |
| D 不退化 | 通过率下降不超过噪声底（按题配对） |
| **护栏** | D 上“翻 git 历史 / 碰隐藏测试”的次数不上升（先把 INTEGRITY_SUSPECT 规则补上 `git checkout/show/diff/stash` 题目文件） |
| 拐杖判定 | 在 C 上做 2×2（训练前后 × 契约开关）：训练后契约的收益缩小或翻负 |

证伪：A、B 有提升而 C 没有 → 只在模板或 JSON 环境里学会；A、B、C 都有而机制指标不变 → 学到了别的捷径，看轨迹。

# 从失败归因到模型—Harness 共同进化：在 Terminal-Bench 上的一次完整闭环实验

**时间：** 2026-09-21 至 2026-09-28（8 天）
**作者：** 武越
**仓库：** `agent_harness/`（决策日志 `decisions.md` D-001–D-083；预注册 `HYPOTHESES.md`；实验日志 `docs/LAB_NOTEBOOK.md`）

---

## 摘要

Coding agent 在 Terminal-Bench 这类终端任务上失败时，责任在模型、在 harness（包裹模型的那层控制程序：提示词、工具接口、等待策略、交卷确认），还是在题目本身？这个问题决定了应该把资源投到训练还是投到工程上。本项目用一条可复用的评测流水线回答它，然后把"模型侧"的残余真的拿去训练，看闭环能不能转起来。

分四个阶段。**阶段一**（被测模型 Seed 2.1 lite，Terminal-Bench 2.1 的 41 道题）建立失败归因流水线，验证 LLM 判官的可靠性，对 Terminus 2 做了两圈共 9 个 harness 改动的逐机制消融，并用"改题不改 harness"和"强模型重跑"两种对照做归责。**阶段二**（被测模型换成可训练的 Qwen3-Coder-30B-A3B，自己的 vLLM）做四个 harness 的同批对照，把 Qwen 的失败按"harness 修得掉 / 修不掉"拆开。**阶段三**在 111 道自己合成的任务上，用 Qwen 自己的成功轨迹做拒绝采样微调（RFT / LoRA SFT），比较了四种数据来源。**阶段四**做 PSP 式的 GRPO 强化学习，难题上由强模型实时给提示，并测量提示是否迁移。

主要结果：（1）在 Seed lite 上，9 个 harness 改动在同批对照和实测噪声底（8 pp）下没有一个带来可复现的通过率提升；唯一稳定收益是 `adaptive_wait` 的效率（空等待轮 −27%、token −11%）。（2）判官作为"失败现象"分类器可用（与人工宽松一致 97%），作为"归责"分类器不可靠（严格 κ 0.6 左右是天花板）；判官自身复判一致率只有 77%。（3）Terminal-Bench 2.1 的 41 题里 7 道被证实存在题面或测试缺陷，改题面后 extract-elf 从 0/6 变 3/3。（4）在 Qwen 上，接口修补把格式错误轮减少 93%，但通过率只 +5–6 pp、不显著；"明知没做成仍宣布完成"在所有 harness 下都占失败的 23–31%，判为模型侧。（5）SFT 与 RL 在留出的新题和 TB 上都没有可测的提升（RL − 原版 = +0.0 pp [−7.2, +7.2]）；第一次评测里 SFT 把假成功率从 11% 压到 4% 的"显著"效果，在同时重跑的重复评测里没有复现。（6）实时 Teacher 提示能让 8 次全挂的难题产生 25% 的通过率和训练信号，但撤掉提示后同一批题从 72% 掉回 8%（第 9 步，11 道题），不带提示的试做全程合计 8/282：提示带来的成功没有迁移。

阴性结果之外，这个项目沉淀了一套方法论：先测噪声底，预注册预测，对照臂同时跑，子集效应必须由事后独立批次复现，判官必须先测自身一致率，多臂比较不挑赢家。这些规则每一条都是被某次"乐观读数"教出来的。

## 1. 研究问题

### 1.1 问题的来源

这个项目起于三条线索的交汇。

**实习的方法。** 在此前的 coding agent 数据实习中，我参与了三套面向 coding agent 后训练数据的流水线：teacher-guided rollout（强模型在学生做题过程中给提示，筛选学生自己的成功轨迹）、task engine（造题、oracle / NOP 校验、失败分类）、bad-pattern 定向合成（对比强弱模型轨迹提炼弱模型的坏模式，针对性造题）。它们都默认失败可以归到"模型的能力短板"上，然后用数据去补。但同一个模型换一个 harness，分数能差十几个点：哪些失败其实是 harness 造成的？这在实习的流水线里没有被系统回答过。

**业界的需求。** agent harness 与 agent 评测方向的工作反复出现同一组词：trajectory analysis → failure patterns → 具体的 harness 改进；自动化评测（规则 / 模型 / 人工三层判定）；"模型与 harness 共同进化"；评测 → 数据 → 训练的闭环。这要求把"归责"做成可验证的实验，而不是靠读几条轨迹下判断。

**文献里的空白。** 已有工作要么固定 harness 改模型（后训练论文），要么固定模型改 harness（agent 框架论文），每个设置通常只跑一次，也很少报告同配置重跑的噪声。两边都没有回答"同一批失败，换 harness 能修多少、换模型能修多少"。

### 1.2 主问题与子问题

**主问题：** 对一个固定的被测模型，它在 Terminal-Bench 上的每一类失败，能不能通过跨配置对照实验归到模型侧、harness 侧、题目侧或环境侧；归到模型侧的部分，用模型自己的轨迹训练能不能修掉。

拆成五个可以分别证伪的子问题：

| 编号 | 子问题 | 回答方式 |
|---|---|---|
| Q1 | 只改 harness，能把失败修掉多少？ | 同批并行的逐机制消融（阶段一 9 个改动、阶段二 4 个 harness） |
| Q2 | 自动归因判官可信吗？ | 两家判官互查、措辞不变性、复判一致率、人工仲裁 κ |
| Q3 | 判官说的"题目不清"是真的吗？ | 改题不改 harness（E8），题目质量审计 |
| Q4 | harness 修不掉的残余，用模型自己的轨迹训练能不能修？训练后 harness 还需不需要？ | 合成题上 RFT / RL，留出题评测，harness × 训练的 2×2 |
| Q5 | 难题上强模型的提示怎么进训练才不会让模型依赖提示？ | 三种提示方式对照，提示依赖度与不带提示试做 |

## 2. 方法论约束（以及为什么定这些规矩）

下面这些规则在项目开始时只有前四条；其余是被某次乐观读数教出来后追加的（追加的时间和触发事件写在括号里）。

1. **先测噪声底，再谈效果**（D-013）。同配置重跑两次的差值就是噪声底，任何小于它的"提升"不算数。理由：每设置只跑一次是两篇参考论文自己承认的 limitation。
2. **预注册**（D-014）。改 harness 之前把每个改动针对什么失败模式、预测多少、什么算证伪写进 `HYPOTHESES.md`，之后只能追加不能改。跑完只填结果列。
3. **判官模型家族 ≠ 被测模型家族**（D-003）；判官看不到 reward 和推理过程；过早完成只用规则判、不交给判官（D-016，依据 False Success 论文：判官会被措辞骗）。
4. **全关时与上游逐字相同**。所有 harness 改动做成 fork 里的开关，全部关闭时发给模型的提示与上游 Terminus 2 字节一致，有金标测试保证。这样"基线"就是上游本身，不是"我们改过的东西再关掉"。
5. **对照臂必须与基线同时并行跑**（D-040，2026-09-25）。触发事件：同配置隔 3 小时重跑差 11.5 pp，原来的 8 pp 噪声底是低估。
6. **子集效应写进结论前，必须有一个在提出该效应之后才跑、判定口径预先写死的独立批次复现**（D-036 / D-050，09-24 / 09-26）。触发事件：契约在模糊题上的 +13.9 pp 逐批缩到 +4.8 pp、最后一批反号。
7. **判官必须先测自身复判一致率**（D-035，09-24）。触发事件：措辞扰动实验的对照组（原文不改、重判一次）自己就翻转 23%。
8. **每个 harness 开关必须指向一个有计数的失败模式，没有就别加，没用的要删**（D-038 / D-039，09-25）。
9. **多臂比较不挑赢家，所有跑过的臂一起报**（D-046）。
10. **不蒸馏**（用户 09-26 定）：训练数据里每个 assistant token 都必须是被训模型自己生成的；别的模型只能出题、给提示、写评分细则、判分。
11. **防污染**：Terminal-Bench 2.1 全部 89 题只做评测；合成题的出题模型只拿到一句抽象技能描述，成题后与 TB 做 5-gram 重合比对。
12. **花钱前先给详细计划、等明确同意**（用户 09-27 定，在一次约 30 美元的 GPU 空转和一轮无效的提示实验之后）。

## 4. 阶段一：Seed lite 上的失败归因与 harness 消融（09-23 至 09-26）

### 4.1 基线、噪声底、强模型对照

- **E0 oracle 检查**：56 题里 53 题参考解通过，3 题因验证器问题剔除，主清单定为 41 题。
- **E1 基线**：Seed lite × 上游 Terminus 2，41 题 × 3 次：trial 级通过率 68.3%，pass@3 82.9%，成本 0.155 元 / trial。
- **E1n 噪声底**：同配置 10 题 × 5 次跑两轮：60.0% vs 68.0%，**δ = 8 pp**。这证伪了事先的元假设"噪声在 ±3–5 pp"。后来（D-040）发现连 8 pp 都是低估：同配置隔 3 小时重跑差 11.5 pp，最终把噪声底写成一个分布（题级差的绝对值中位 4–11 pp），8 pp 作为最低门槛。
- **E2 强模型**：gpt-6-sol 同 41 题 × 1 次：92.7%，比 Seed +27.5 pp [+16.7, +39.2]；0 超时、0 空转。

### 4.2 失败分类与归因流水线

分类顶层对齐 Terminal-Bench 论文的三大类（Execution / Coherence / Verification），另加环境与题目两类。三层判定：

```
Harbor 输出 ──▶ 规则层（纯函数：PREMATURE_COMPLETION、BUDGET_EXHAUSTED、POLLING、LOOP、
                 TRUNCATED_READ、COMMAND_NOT_FOUND、INTEGRITY_SUSPECT…；环境类先判且排他）
            ──▶ 判官层（gpt-6-sol：主标签 / 起始轮 / 置信度；另出十类动作编码、题面清晰度 0–3）
            ──▶ 人工层（同一 schema，source=HUMAN）
            ──▶ 归责（跨配置二维表：换模型变不变 × 换 harness 变不变 → MODEL / HARNESS / MIXED）
```

关键设计：**归责由跨配置的实验决定，判官只提候选**（D-007）。理由是实习时的原则"执行类证据硬否决，判官不能推翻"。

E1 的读数：规则层把 64% 的失败标为"没验证就宣布完成"；判官把这 25 条拆成题意误读 12、验证不足 8、题目本身不清 3、无法判断 2。这个拆分直接决定了第一圈改哪些开关。另外，41 题里 14 题（34%）被判"题面模糊"，这类题的基线 52.4%，清晰题 76.6%。

### 4.3 第一圈 harness 改动：六臂消融

按判官分布选了三个开关，各对一类失败：`task_contract`（首轮只读，列出需求与模糊点；对题意误读）、`verifier_gate`（完成前把关，分 `self_check` 同对话自查和 `auditor` 独立审计两档；对验证不足）、`adaptive_wait`（用 tmux 哨兵等命令真正结束，不再让模型猜等待时长；对空等待）。另加三个顺手的：卡死提醒、预算提示、退出码提示。

26 题 × 3 次，同批重跑基线（61.5%）：

| 臂 | Δ 通过率（pp） | 95% 区间 | 机制指标 | 判定 |
|---|---|---|---|---|
| task_contract | +7.7 | [−1.3, +17.9] | 判官标签里题意误读 13 → 9 | 不确定（< δ，区间跨零） |
| self_check | +6.4 | [−2.6, +15.4] | 验证不足只从 5 减到 4 | 不确定 |
| auditor | +0.0 | [−11.5, +10.3] | 89 次审计、22 次打回；成本 +29%；超时 10 → 17 | 无效：打回是对的，但模型补不完 |
| hygiene 三件套 | −1.3 | [−12.8, +10.3] | 卡死提醒一次都没触发 | 无效，退役 |
| adaptive_wait | −2.6 | [−14.1, +9.0] | 空等待轮 −27%、轮数 −0.6、输入 token −11% | 通过率不变，效率收益稳定 |

结论：通过率上没有一个改动越过噪声底。能说的只有方向和机制。

`adaptive_wait` 还顺带发现了上游的一处死代码：Terminus 2 的 `_execute_commands` 里 `except TimeoutError` 永远不会触发，因为非阻塞路径从不抛异常；整理成了 Harbor 的 PR 草稿（`docs/harbor_pr_draft.md`），并在 SWE-bench Verified 上验证了同方向的效率收益（用时 −32% [−51%, +4%]）。

### 4.4 强模型上的"拐杖判定"

同一个改动在强模型上再跑一遍（gpt-6-sol，同 26 题 × 2 次）：只对弱模型有用、强模型不涨反而多付钱的，叫"拐杖"；两种模型都受益的，叫结构性改进。

| 改动 | 弱模型 Δ | 强模型 Δ | 强模型成本 | 判定 |
|---|---|---|---|---|
| task_contract | +7.7 | +0.0 [−12.0, +12.0] | +57% | 拐杖 |
| self_check | +6.4 | −2.1 [−12.5, +8.3] | +79%，轮数 11.6 → 20.5 | 有害：强模型本来就会自检，再逼它多走一遍只是把轮数翻倍 |
| adaptive_wait | −2.6（效率 +） | 未跑（不改变模型决策） | — | 结构性（省资源型） |

### 4.5 判官可不可靠：一条不断修正的链

五个改动没有一个越过 δ，有两种可能：改动没用，或者靶子选错了。靶子来自判官，所以先查判官。这一段每个数字都被下一个实验修正过：

| 步骤 | 读数 | 引出的下一步 |
|---|---|---|
| 两家判官互查（gpt-6-sol vs claude-sonnet-5，39 条失败） | 主标签 κ 0.49（预注册要 0.80，证伪）；分歧集中在题意误读 / 验证不足 / 过早完成三个相邻标签 | 把次标签也算上，宽松一致 79.5% |
| 措辞不变性（只改写模型自述的口吻，命令与输出不动） | 更自信翻转 27%，更犹豫翻转 30% | 看似判官只看措辞 |
| **对照组：原文不改、重判一次** | **也翻 23%** | 真正的发现：判官自身复判一致率只有 77%。任何判官比较都要先扣掉这个底噪（D-035） |
| 人工仲裁 13 条难例 | 判官 vs 人 κ 0.30；8 条"题面缺信息"判官只对 2 条；两条 overfull-hbox 判官编造了证据 | 系统性偏差：判官把"题面缺信息"判成"模型误读" |
| 给判官全部 context（隐藏测试 + 参考解 + 完整验证器输出） | κ 0.30 → 0.40 | 之前"半盲"的设计是错的（D-037）：归因判官的任务就是对照"题面说了什么"和"测试要什么"，不给测试等于让它猜 |
| 三票多数投票 | κ → 0.50 | — |
| 把人工仲裁定下的五条判定规则写进提示（v3） | κ 0.62，宽松一致 97%（样本内）；样本外 15 条 0.57，与旧判官持平 | 规则消掉的是系统性归责错误（题面缺信息 3/8 → 6/8），不是提高天花板 |
| 换 5 倍价格的 gpt-6-astra | κ 0.55，不如 sol 三票 | 瓶颈在证据完整度、标签定义和判官随机性，不在模型档位（D-045） |
| 两家 v3 共识 | 一致 22/39；一致时对人工正确 86%，不一致时各只有 47% / 24% | 最终设计：**双判官一致就采信、不一致送人工**，自动定案 56%、准确率 86%（D-044） |

39 条 E1 失败全部人工定案后的分布：题面缺信息 8、验证不足 8、能力 9、预算耗尽 8、题意误读 5、环境 1。**第一圈的靶子"题意误读 36%"大部分其实是题面缺信息**，契约对着一个多半不存在的靶子打。

### 4.6 改题不改 harness：判官说的"题目不清"是真的吗（E8 / E8b）

对判官标了 TASK_UNDERSPECIFIED 的 5 道题，只补题面里缺的接口约定、不给解法（D-032），Seed lite 重跑 3 次，另留一道题面清楚、失败原因是预算耗尽的 path-tracing-reverse 不改作对照：

| 题 | 改题前 | 改题后 | 读法 |
|---|---|---|---|
| extract-elf | 0/6 | **3/3** | 题面示例地址与参考实现自相矛盾（PIE 基址约定），是真缺陷 |
| cancel-async-tasks | 2/6 | 3/3 | 取消语义没说清 |
| chess-best-move | 2/6 | 2/3 | 无变化，失败是看图认子（能力） |
| raman-fitting | 0/6 | 0/3；补到底（E8b）仍 0/3 | 缺的是 1e7/x 这条领域知识，改题面救不了；补上换算后峰位全对、仍卡在题面没给的拟合窗口 |
| dna-insert | 1/6 | 0/3；E8b 3/3 | 边界约定 + 环境里 oligotm 版本与验证器不一致（同一序列判定相反）：题 + 环境 |
| path-tracing-reverse（对照） | 0/6 | 0/3 | 不变，如预期 |

→ D-034：判官的"题目不清"要拆成**接口约定 / 领域知识 / 环境工具**三类，只有第一类改题就好。最终形成 41 题的任务质量审计（`docs/task_audit.md`）：Seed 失败过的 15 道题里 7 道被证实存在题面或测试缺陷。这一步的方法论意义是：判官的标签必须能被"改题"这种干预实验验证，否则只是意见。

### 4.7 第二圈：对着人工核实后的坏模式改

人工仲裁修正了靶子：7/39 次失败超时时交付文件根本不存在；6/24 条是"自测通过但和验收方式不一样"（同一 shell 里 export 再 which、只测 REPL 不测全屏程序）。第二圈只做两个对着这两类的开关，三臂并行（D-040）：

| 臂 | Δ 通过率 | 机制 | 成本 | 判定 |
|---|---|---|---|---|
| deliverable_checkpoint（8 分钟起每 3 分钟查交付文件存不存在） | −5.1 [−15.4, +3.8] | 无交付的失败 11 → 6，触发 51 次 | −17% | 机制成立，通过率证伪："先写个答案"让文件存在了，写进去的多半是错的 |
| grader_check（完成前按四条清单像验收方一样验一遍） | −6.4 [−19.2, +6.4] | 超时 9 → 34，轮数 15.9 → 43.3 | +110% | 证伪，且是代价最大的一次：模型把 15 分钟全用在验证上 |

→ D-047 的核心教训：**在有硬时限的 benchmark 上，任何让模型多走轮次的提示类干预都自带负项；验证类干预的真实代价是时间，不是 token。** 若要做，必须由 harness 在容器里执行检查、把结果塞回观察，不占模型轮次。

同期离线做了 H14（用自测证据从 3 次 rollout 里挑一次）：按预注册规则选中 50.0%，比随机选（61.5%）还差，pass@3 上限 73.1%。模型的自述不是可用的选择信号。

### 4.8 契约的"条件式效应"及其不复现（本阶段最重要的方法论事件）

E4p 把契约加样到 41 题 × 3 次，并第一次按子集拆开看：

| 口径 | 基线 | 契约 v1 | 契约 v2（用户提议：识别 → 推理 → 决策） |
|---|---|---|---|
| 全集 | 76.4% | 74.0%（−2.4） | 76.4%（+0.0） |
| 模糊题 14 道 | 61.9% | 69.0%（+7.1） | 71.4%（+9.5） |
| 清晰题 27 道 | 84.0% | 76.5%（−7.4） | 79.0%（−4.9） |

三批合并后模糊题 +7.6 [−0.0, +17.2]，下界正好压零。当时的解读（D-048）：契约是条件式手段，模糊题的收益被清晰题的损失抵消，所以全集看不出效果。顺理成章的下一步是 H17：**只在题面模糊时启用契约**。

H17 开跑前做了两件事：（a）用已有数据核对预注册的开关，发现"首轮列出模糊点就开"在清晰题上 96% 都会开，等于没有开关；离线预检三种开关后换成"开跑前单独调一次模型给题面打清晰度分"（模糊题开 90%、清晰题误开 27%）；（b）算术上限检查：即使开关完美，全集上限也只有 14/41 × 7.6 ≈ +2.6 pp，原预测"+2 到 +6"不可达，撤回，改为按子集判定。分析脚本在拿到数据前写死并在旧数据上试跑。

结果：开关完全按设计工作（模糊题开 86%、清晰题误开 30%），但模糊题 −4.8、清晰题 +2.5、全集 +0.0，预注册判定不成立。**更重要的是把 H17 当作契约的第四批去复查**：

| 批次 | 模糊题 Δ | 清晰题 Δ |
|---|---|---|
| E4 → E4t → E4p → H17 | +13.9 → +4.8 → +7.1 → **−4.8** | +2.4 → — → −7.4 → **+3.7** |
| 四批合并 | +4.8 [−3.0, +13.1] | −4.9 [−13.0, +2.5] |

两个方向都没有复现。D-050 撤回 D-048：**契约在任何粒度上都没有可复现的效果。** 事后看，第 6 阶段有三个该警觉的信号：子集是在看到 +13.9 之后才被当成重点的（选择在结果之后）；两个方向恰好对称、各有一个机制故事，太干净；合并区间下界正好是 0。H17 的价值在于它是**在提出效应之后才跑、判定口径预先写死**的独立批次，所以结果没有解释空间。

契约 v2 还有一个反直觉发现：账本命中决定性细节的比例 v1、v2 都是 80%，但命中之后的通过率 v1 是 8/12、v2 只有 3/12。强制逐点写 resolutions 让模型在已经想对的地方改主意。识别和决策是两件事。

### 4.9 换基准找 harness 提分的余地

Seed lite 在 SWE-bench Verified 上基线 75%（15/20）、SWE-bench Pro 90%（9/10）、Terminal-Bench 4.0 在 100 轮预算下 0/10。没有一个落在能测出 harness 提分的 20–50% 区间：代码修复类题 Seed lite 已经很强，前沿终端题在我们的预算下又完全做不出来。按事先约定停止这条线。

### 4.10 阶段一小结

对 Q1–Q3 的回答：在 Seed lite 上，harness 侧能稳定拿到的只有效率收益；通过率上的失败要么归题目（接口约定缺失，改题就好）、要么归模型（预算耗尽、截断读取、领域知识）。判官作为"现象"分类器可用、作为"归责"分类器不可用，归责必须靠改题、换模型、换 harness 三向对照。

这一阶段也暴露了继续用 Seed 的两个问题：它太强（TB 68%、SWE-bench 75–90%），harness 没有提分空间；它不能训练，闭环转不到"训练"那一步。于是换模型。

## 5. 阶段二：Qwen3-Coder-30B-A3B 的四个 harness 对照（09-26 至 09-27）

### 5.1 为什么是这个模型

需要一个通过率在中段、失败模式明确、能自己训练的开源模型。Qwen3-Coder-30B-A3B 是 MoE（激活 3B），bf16 权重 61 GB，一张 H200 能同时做推理和 LoRA 训练。

### 5.2 阶段 0：先看它的毛病

先经 OpenRouter 在审计后干净的 30 道 TB 题上跑 3 次（90 trial）。第一次冒烟 0/2、大量"找不到合法 JSON"，追查发现是服务商问题：把 Terminus 的开场提示原样发给各服务商各 6 次，Novita 5 次返回空内容（D-052）。固定用 Alibaba 官方服务后重跑，通过率 20%（18/90），三种毛病按规则统计（对照 Seed lite 与 gpt-6-sol 同口径）：

| 毛病 | Qwen | Seed lite | gpt-6-sol |
|---|---|---|---|
| 回复不是 Terminus 要的 JSON（字符串里直接换行） | 50% 的 trial；平均每 trial 浪费 4.9 轮 | 1% | 0% |
| 用 echo 打印"✓ 完成"代替运行检查（失败 trial） | 51% | 0% | 0% |
| 明知没做成仍宣布完成（失败 trial） | 26% | 3% | 17%（1/6） |
| 命令不存在 | 33/90 trial | — | 31%（同规则重算） |

另有 17 道题 3 次全挂，其中大多数 Seed 与 gpt-6-sol 在同一 Terminus 下能过——是 Qwen 特有的失败。

### 5.3 四个臂的设计与预注册

原则（QWEN_PLAN §0）：**harness 改动便宜、立刻生效、可撤回；训练要数据、GPU 和时间。所以先测出最好的 harness 能救回多少，剩下的、且强模型在同一 harness 下不犯的，才算训练的责任。**

| 臂 | 配置 | 回答什么 |
|---|---|---|
| H0 | 上游 Terminus 2 原样 | 同批基线 |
| H1 | + 接口修补：宽松解析（只在上游解析失败时介入，离线重放能救回阶段 0 格式错误轮的 90%）、开跑前探测环境里有哪些命令、多行输入卡住时提示 | harness 的"接口不合适"占多少 |
| H2 | H1 + 交卷把关：第一次宣布完成时，若最后一次改文件后没再运行过任何东西、或话里承认没做成，打回一次 | 能把假检查 / 假成功压下多少 |
| H3 | Qwen 官方 harness qwen-code（原生工具调用） | 给它换一个为它设计的 harness 能到多少 |

全部在自己的 vLLM（bf16）上跑，四臂同时启动、各占四分之一并发；30 题 × 2 次，在看到任何结果之前决定再跑同配置第二批（D-057），主分析用两批合并（每题每臂 4 次，共 480 trial）。预注册预测：H1 格式错误轮数下降 ≥ 50%、通过率 +0 到 +5；H2 在 H1 基础上假检查 + 假成功下降 ≥ 50%、通过率 +3 到 +10。

### 5.4 结果与归责

| 臂 | 通过率 | Δ vs H0 | 95% 区间 | 出现过格式错误 | 跑满 100 轮 | echo 代替检查（失败） | 假成功（失败） |
|---|---|---|---|---|---|---|---|
| H0 | 16% | — | — | 57% | 9 | 59% | 30% |
| H1 | 21% | +5.0 | [−5.0, +16.7] | 8% | 1 | 42% | 31% |
| H2 | 22% | +5.8 | [−5.0, +17.5] | 12% | 6 | 49% | 29% |
| H3 | 22% | +5.8 | [−3.3, +16.7] | 0% | 0 | 2% | 23% |

Qwen 自己两批之间的同配置差 ≤ 3.3 pp。

读法：
- **格式错误是 harness 的锅**：宽松解析把每 trial 浪费的格式错误轮从 2.6 降到 0.17（−93%），预注册的"≥ 50%"成立；build-pmars 1/4 → 4/4、log-summary 0/4 → 3/4 都是原来把轮数耗在写坏 JSON 上的题。
- **环境探测没用**：写明了哪些命令没装，模型照样用（40% → 38%）；gpt-6-sol 同规则也有 31%，不是 Qwen 特有。
- **echo 代替检查是接口产物**：Terminus 里模型只能借 echo"说话"；qwen-code 有文字回复的出口，这个现象几乎消失（2%）。它不是训练目标。
- **假成功在所有 harness 下都在（23–31%）**，交卷把关打回了 37/120 个 trial、只有 4 个最后通过：能逼模型去查，查出问题也修不好。H2 的预测被证伪。**这一项判为模型侧，是训练的目标。**
- 通过率上三个改动都 +5–6 pp、都不显著；H2 与 H3 平票，预注册没写平票规则，如实记录后选 H2 采训练数据（数据管线现成，且"harness × 训练"的 2×2 在 Terminus 上最完整，D-059）。

## 6. 阶段三：用 Qwen 自己的成功轨迹做 RFT（09-27）

### 6.1 目标与规矩

训练目标 = 阶段二定出的模型侧残余：明知没做成仍宣布完成、查出问题后不去修。硬规则是不蒸馏：每个训练 token 都是 Qwen 自己生成的；强模型只出题、给提示、判分。

### 6.2 合成题流水线

TB 的 89 题只做评测，训练题要自己造。出题模型（gpt-6-sol）只拿到六个技能族的一句抽象描述和一个场景词（`train/synth/families.py`：正则解析日志、数据格式转换、把小程序移植成 Python、本地 HTTP 服务、git 仓库修复、SQLite 查询），产出题面、工作区文件、隐藏测试（pytest）、参考解（solve.sh），要求"模型能只用 /app 里的材料检查自己的工作"。

校验链：参考解必须通过、什么都不做必须不通过；题面与 TB 全部 89 题做 5-gram 连续重合比对。150 道生成（API 9.72 美元）→ 111 道合格（37 道参考解过不了测试、2 道构建镜像出错）；最大重合只有 0.6%，一道没丢。按技能族分层划分：训练 74 / 留出 37。

**强弱模型排序一致性检验**（实习时常用的方法，D-064）：留出题上 Seed lite 93%（69/74）、gpt-6-sol 99%（73/74）、原版 Qwen 约 14%，方向与 TB 一致（16% / 81% / 91%）。说明合成题能区分能力，但对强模型偏容易、有天花板。

### 6.3 四轮 rollout 与四个 LoRA

原版 Qwen 在训练题上通过率约 15%，每轮只能筛出二三十条合格轨迹，于是逐轮加提示：

| 轮 | 做法 | 通过 / 合格 | 训练版本 |
|---|---|---|---|
| r1 | 74 题 × 3，不给提示 | 31 条合格（20 条来自 git 修复族） | **coderplain** |
| r2 | 同 74 题 × 3，题面末尾加一句通用的"交卷前自查"提示，导出时删掉提示原文；复述提示或提到 hint 的整条丢弃 | 33 条（5 条来自 r1 全挂的题） | **coderlora** = r1 + r2（64 条） |
| r3 | 两轮都没做对的 51 题：gpt-6-sol 读题面 + 参考解，开跑前写 ≤ 5 句思路提示（不给代码、命令、答案），Qwen 做 3 次 | 8/153 通过，隐藏测试平均通过比例 16% → 20% | **coderskill** = r1 + r2 + r3（72 条） |
| r4 | 同 51 题 × 2：**实时 Teacher**——gpt-6-sol 每 6 轮和第一次宣布完成时看 Qwen 最近 10 轮的命令与终端输出（看不到它的思考），对照参考解与隐藏测试，只在走偏 / 卡住 / 忽略报错 / 没做对就交卷时插一句 ≤ 60 词的针对性提示，每条轨迹最多 3 条，判分器不动 | 25/102 通过 | **coderteach** = r1 + r2 + r4 |

r3 → r4 的转折来自用户的一句话："hint 肯定要看他错哪了，甚至实时给，看到卡住就给"。开跑前泛泛讲思路的提示（r3）几乎是复述题面，效果只有 5%；看着错误实时插话的提示（r4）是 25%。这是本项目最干净的一个对比之一（后来在 RL 试点里又复现了一次：§7.2）。

**删提示还是留提示（D-071）。** 原计划训练时把 Teacher 的提示从对话里删掉（context distillation）。但 25 条成功轨迹里 18 条模型"接了提示的话"（"The reviewer pointed out issues with my sorting logic…"），提示一删这些话就没了来由，等于教模型凭空编出 reviewer；不蒸馏的规矩又不允许改写 Qwen 的原话，只能整条丢——只剩 4 条。用户决定不删：提示留在对话里（user 角色，不算 loss），被 Teacher 打断的那句错误的"我做完了"留在上下文但标 `train=False`。于是 22 条可用，coderteach 共 86 条（训练时超过 32k token 的 3 条被丢掉，实际 83 条）。文献检索（PSP、HiLL、ADHint 等，§7.1）后来支持了这个选择：主流做法就是提示留在上下文、不进 loss。

### 6.4 筛选与训练

筛选用规则不用判官（判官之间 κ 只有 0.5–0.6，而这几条行为规则能精确判定、不花钱）：验证器通过；没被把关打回；第一次宣布完成时最后一次改文件后真的运行过东西；宣布完成那轮没有承认没做成的措辞；没发生上下文摘要。

LoRA 只加在注意力层（MoE 的专家层挂 LoRA 会爆显存、vLLM 也不支持），r=16、α=32、lr 1e-4、余弦、2 个 epoch、只对 assistant 轮算 loss、超过 32k token 的轨迹整条丢弃（结尾的检查与交卷最重要，不能截）。四个 LoRA 超参完全相同。训练完在同一个 vLLM 上同时挂原版和四个适配器，先在温度 0 下用 3 道题确认每个适配器的输出与原版不同（防止"挂了没生效"）。

### 6.5 评测设计（D-070，9 组同时跑）

留出合成题 37 × 3：原版 / coderplain / coderlora / coderskill / coderteach（都用 H2）；原版 × H0、coderteach × H0（与前两格组成 harness × 训练的 2×2）；TB 30 × 4：原版 / coderteach。预注册指标：M1 通过率（+5 到 +15 pp）、M2 第一次宣布完成时没运行过检查的比例（相对降 ≥ 30%）、M3 失败 trial 里的假成功率（下降）。

### 6.6 结果（D-076），以及后来的不复现（D-083）

| 版本 | 留出题通过率 | Δ vs 原版 | M3 假成功（失败 trial） |
|---|---|---|---|
| 原版 | 14% | — | 11% |
| coderplain（只用 r1） | 22% | +8.1 [+1.8, +14.4] | 6% |
| coderlora | 16% | +2.7 [−1.8, +8.1] | 8% |
| coderskill | 21% | +7.2 [+0.0, +15.3] | 8% |
| coderteach | 16% | +2.7 [−0.9, +6.3] | 4%（−7.8 [−13.7, −2.0]） |

当时的读法：加入带提示的数据没有带来额外提升（最好的反而是只用普通轨迹的 coderplain）；coderplain 的 +8.1 刚好卡在 8 pp 线上、又是四个版本里挑出来的一个，要打折扣；最站得住的是 coderteach 把假成功率从 11% 压到 4%。2×2：训练没有让模型学会 H0 下的格式（格式错误仍 53%），交互项 +3.6 [−0.9, +9.0] 不显著。

**次日的最终评测（§7.7）把原版和 coderteach 同时重跑了一遍：通过率 16% vs 14%（−2.7），假成功 10% vs 9%。M3 的效果没有复现。** 所以 SFT 的效果应当看作 ≈ 0，"M3 是最稳的训练效果"这句话作废。这是本项目第二次被重复评测抓出假阳性（第一次是契约的子集效应），也是第 6 条规矩存在的理由。

按题型拆开（描述性）：git 修复族 53% → 67–80%（训练数据里一半是它）；port-program 0% → 6–17%；log-regex 与 local-service 各版本都是 0。训练后的模型每题多做几轮（44 → 47–51），在评测负载高时更容易撞 15 分钟上限（超时 12–14% vs 原版 7%）。

## 7. 阶段四：PSP 式 GRPO（09-27 晚至 09-28）

### 7.1 为什么做 RL，以及文献怎么处理带提示的 rollout

SFT 只从做对的轨迹学，对"没做对却宣布完成"没有任何惩罚；RL 按判分器给奖励，错误交卷直接拿负的 advantage。但 RL 在 8 次全挂的难题上没有信号，需要提示。文献里带提示的 rollout 有四种进训练的方式：

| 做法 | 训练时怎么处理提示 | 代表 |
|---|---|---|
| A 留在上下文，不进 loss | 训的是"带提示时的模型"，测试时不给 | PSP（2609.29051，多轮 agent）、QuestA、SAGE |
| B 删掉，按 token 做概率修正 | 训"不带提示的模型"，每个 token 乘 π(y|x)/π(y|x+hint) | Guide-GRPO、Off-Context GRPO（数学） |
| C 直接删掉 | 当成模型自己写出来的 | STaR（SFT 时代）；RL 里被认为会让训练不稳 |
| D 蒸馏掉 | 带提示的自己当老师 | OPSD、Ahead、Action Guidance |

共识只有三条：全错时要给提示；提示别直接给答案；不修正就直接删（C）最不被看好。A 与 B/D 之间没有定论；PSP 报告 OPSD 会让 agent"表现得好像知道它没看到的信息"，甚至低于原版。我们选 A（最简单、完全 on-policy），并把它的主要风险——模型依赖提示——做成两个可测的量（§7.4）。

### 7.2 设计，与难题提示方式的小试点

设计（D-072 / D-073）：每步 16 道训练题 × 8 次（H2，采样设置同评测）；判分器 0/1；组内标准化 advantage，全对或全错的组跳过；每步只更新一次 LoRA（完全 on-policy，重要性比恒为 1，不需要裁剪；不加 KL，靠 LoRA、步数少和止损约束）；loss = −Σ A·Σ log π(Qwen 自己的 token) / Σ T（DAPO 式按 token 归一）；从原版起步（policy00 = LoRA B 为 0）；20 步预算。难题提示留在上下文、不进 loss。

难题提示有两种候选：A = PSP 式开头规则（gpt-6-sol 读该题 6 次失败记录 + 参考解 + 隐藏测试，写 3–6 条 ≤ 35 词的行动规则放在题面最前）；B = 实时 Teacher（§6.3 r4）。用户要求先做小实验再定。预注册决定规则：A 通过率 ≥ 15% 用 A，否则用 B。

试点第一次与 9 组评测同时跑，44 条并发让每轮慢一倍、超时激增（前 14 次 6 次超时，B 当初 102 次只超时 2 次），比较不公平，中止；评测结束后在与 B 相同的条件下重跑（D-074）：

| 提示方式 | 通过 | 至少做对 1 次的题 | 隐藏测试平均通过比例 |
|---|---|---|---|
| r3 开头思路提示（不看失败） | 8/153（5%） | 7/51 | 20% |
| A PSP 式开头规则（看过失败） | 6/102（6%） | 6/51 | 25% |
| B 实时 Teacher | 25/102（25%） | 17/51 | 44% |

A − B = −18.6 pp [−28.4, −9.8]。**同样读过失败记录，一次性放在开头几乎没用，做题中途看到走错再插话才管用。** 按预注册规则用 B。

### 7.3 实现与验证

`train/rl/grpo.py`（组内 advantage、提示模式切换、trial → 样本）、`grpo_step.py`（GPU 上的一次更新：只在 Qwen 自己的 token 位置分块算 logits，允许 64k 的长失败轨迹进训练；Adam 状态跨步保存）、`grpo_loop.py`（主循环：Harbor 采样 → 收集 → 更新 → 换适配器 → 重写规则 → 止损；可断点重跑）。测试用一个极小的随机模型确认 advantage 为正时 log-prob 上升、为负时下降，分块 NLL 与标准 loss 一致。冒烟 2 步 × 4 题 × 4 次通过后开正式跑。

### 7.4 提示依赖的两项检查（D-075）

（a）**提示依赖度**（HiLL 的定义）：对带提示且做对的轨迹，去掉提示再算一遍同一批 token 的平均 log-prob，差值越接近 0 越不依赖。只记录，不改训练。（b）**不带提示的试做**：带提示的题每步另做 2 次不带提示的，不进训练；试做做对过就下次撤掉提示（更接近 PSP / Guide 每次先试不带提示的做法）。

### 7.5 运行过程

正式 RL 于 09-28 00:25 开跑，每步约 65 分钟（做题 50 + 训练与重启 13），每步约 9 美元（含 Teacher API 约 4 美元）。夜间按授权自己处理。

**中途的多 agent 审查（D-079）。** RL 开跑前用 5 个角度 × 3 个质疑者的 workflow（102 个 agent）审查 RL 代码，报告 32 个问题、28 个经复核保留。两个高严重度：

1. **loss 算概率的分布和实际采样不一致。** vLLM 按模型自带的 generation_config 采样（温度 0.7、top-k 20、top-p 0.8、重复惩罚 1.05），而 loss 按温度 1、整个词表算 log-prob。两边不一致时梯度多出一项与奖励无关的偏置，大小正比于 Σ A·T，失败轨迹更长时它会把确定的 token 压平。修正：按 vLLM 的顺序（重复惩罚 → 温度 → top-k → top-p）重算 log-prob，测试与一份照抄 vLLM 采样器的参考实现逐行比对。修好后"采到的 token 不在重算候选集里"的比例 0.2%，梯度范数从 0.02 降到 0.006–0.011（旧梯度里一大半是这项偏置）。
2. **自动止损规则会误停。** 它比较的是不同的题、带不带提示也不同；模拟显示策略不变时约 85% 会误停。改成只比同一道题、同一种模式。

在第 4 步的做题阶段只结束主循环进程、让外层流程用新代码拉起，从断点续跑。代价：第 1–3 步用的是旧的 log-prob，第 4 步起是新的，报告里注明。

第 5 步检查点（D-080）和第 9–10 步（用户决定 D-081）都维持设计不变：训练方式已中途改过一次，再改题目比例会让结果更难解释。

### 7.6 训练侧结果（D-082）

14 步后因预算上限自动停（125.6 美元，超额度 5.6 美元是"每步开始前检查"的已知行为）。74 道训练题都至少出现了两次，比较每题第一次和最近一次：

| 情况 | 第一次 | 最近一次 |
|---|---|---|
| 两次都不带提示（21 道） | 52% | 54% |
| 两次都带 Teacher（46 道） | 18% | 16% |
| 带 Teacher 做过、后来撤掉（跑完时仍处于撤掉状态的 5 道） | 带 Teacher 时 58% | 撤掉后 20% |
| 同上，第 9 步时的快照（11 道） | 72% | 8%（其中 6 道撤掉后又挂了、被切回带提示，所以跑完时只剩 5 道） |
| 带 Teacher 的题，不带提示试做 | 1/92 | 2/92（全程合计 8/282） |

提示依赖度均值 0.027（按 HiLL 的标准属于低），Teacher 调用 4124 次、0 次出错，LoRA B 范数 0 → 0.51。**14 次参数更新后，训练题上两种模式都看不到可测的进步；Teacher 让难题有对有错、产生了学习信号，但没有迁移到不带提示的情况。** 中午我据此给出的预测（新题上 0 到 +5 pp、不显著、假成功率不会低于 SFT）与最终结果一致。

### 7.7 最终评测（D-083）

原版 / coderteach（SFT）/ rlpolicy14（RL）三臂同时跑，留出题 37 × 3、TB 30 × 4，全程不给提示：

| 集合 | 原版 | SFT | RL | RL − 原版 | RL − SFT | SFT − 原版 |
|---|---|---|---|---|---|---|
| 留出题通过率 | 16% | 14% | 16% | **+0.0 [−7.2, +7.2]** | +2.7 [−6.3, +12.6] | −2.7 [−8.1, +2.7] |
| 留出题假成功（失败 trial） | 10% | 9% | 17% | — | +8.1 [−1.6, +17.7] | — |
| TB 通过率 | 24% | 18% | 21% | −3.3 [−12.5, +5.8] | +3.3 [−1.7, +9.2] | −6.7 [−15.8, +2.5] |

预注册的三条预测（RL − 原版 +5 到 +15；RL 不低于 SFT；RL 的假成功低于 SFT）全部不成立。

## 8. 实验中遇到的问题与解决

### 8.1 方法上的

| 问题 | 怎么发现的 | 怎么解决 |
|---|---|---|
| 噪声底被低估（8 pp → 实际 4–11 pp） | 同配置隔 3 小时重跑差 11.5 pp（D-040） | 对照臂必须与基线同时并行跑；噪声底写成分布 |
| 契约的子集效应逐批缩水、最后反号 | 把 H17 当作契约的第四批复查（D-050） | 子集效应必须由事后独立批次复现；下界贴 0 不算证据 |
| 判官"半盲"导致系统性归责错误 | 人工仲裁：8 条题面缺信息判官只对 2 条（D-037） | 给全 context；人工判定规则写进提示；双判官共识 + 人工兜底 |
| 判官自身不稳定 | 措辞扰动的对照组也翻 23%（D-035） | 温度 0 + 三票多数；复判一致率作为判官第一项验收指标 |
| 第二判官 39 条里 23 条正文为空 | κ 算出 0.24 全是假分歧（D-031） | Claude 5 系列要用 adaptive thinking，max_tokens 加上思考预算；空输出当错误不当 CANNOT_JUDGE |
| 预注册的 H17 开关没有区分力 | 用已有数据核对：清晰题 96% 都会开（D-049） | 离线预检三种开关再定；预测先做算术上限检查 |
| 验证类干预让模型把时限全用在验证上 | grader_check 超时 9 → 34（D-047） | 只做不占模型轮次的干预 |
| 提示删掉后成功轨迹只剩 4 条 | 18/25 条模型接了提示的话（D-071） | 提示留在上下文、不进 loss；错误交卷标 train=False |
| 试点与评测同时跑，负载不公平 | 超时 6/14 vs 2/102（D-074） | 中止，评测后在相同条件下重跑 |
| loss 与采样分布不一致 | 多 agent 审查（D-079） | 按 vLLM 采样器重算 log-prob，切换时重置 Adam |
| SFT 的 M3 效果是假阳性 | 次日同时重跑的重复评测（D-083） | 结论作废；重复评测成为默认要求 |

### 8.2 基础设施上的

| 问题 | 原因 | 解决 |
|---|---|---|
| SWE-bench Pro 题 tmux 起不来 | `--ae KEY=…` 让 Harbor 用 `tmux -e` 注入变量，老镜像的 tmux 不认；而且这把真 key 暴露给了被测模型的终端 | 去掉 `--ae`（模型调用在宿主机，容器不需要 key）；核对所有轨迹无 key 外泄（D-051） |
| Qwen 第一次冒烟 0/2 | 服务商 Novita 返回空回复 | 各服务商先做 6 次空回复检查；固定 Alibaba 官方服务（D-052） |
| vLLM 起不来 | pip 装到的 0.30 按 CUDA 13 编译，机器驱动只到 12.8；"能 import"甚至 `cuda.is_available()` 都不能发现 | 固定装 cu129 wheel；安装检查改为真往 GPU 放张量（D-053） |
| 两轮采样同时跑，283 个 trial 作废 | Harbor 每个 trial 建一个 Docker 网络，默认地址池只有约 31 个 | 地址池改成 1024 个；用 `harbor jobs resume` 只补跑基础设施报错的 trial（D-062） |
| LoRA 训练被重跑一遍 | SSH 会话断开被包装脚本当成"没连上"而自动重试整条命令 | 有副作用的命令不放进自动重试；长任务一律后台 + 完成标记（D-066） |
| 推理服务没起来，GPU 空转 35 分钟 | `pkill -f "vllm serve"; …; vllm serve …` 写在同一条远程命令里，pkill 匹配到执行它的 shell | 关、起都放进脚本文件（D-077） |
| RL 主循环在第 1 步训练后退出 | `cd … && setsid … &` 让整个复合命令进后台、占着 SSH 连接直到训练结束，超过 90 秒时限 | 统一的后台启动函数，用 `;` 只让训练那条命令进后台；在 Linux 上真跑测试（D-078） |
| 写规则的脚本 47/51 题读不到失败记录 | Harbor 把目录名里的题名截到 32 个字符 | 按 result.json 里的完整题名匹配；加检查：任何题读不到失败就停 |
| 大规模文本编辑题上回复停不下来 | 模型陷入重复生成直到上下文装满（重放 3 次 1 次复现） | 实验中途不改配置（各臂共用同一服务，公平）；报告单列；下一轮候选改动是单次回复上限（D-058） |

## 9. 结论

### 9.1 对研究问题的回答

- **Q1（harness 能修多少）：** 在 Seed lite 上，9 个改动没有一个带来可复现的通过率提升；在 Qwen 上，接口修补把格式错误轮减少 93%、通过率 +5–6 pp 不显著。harness 能稳定修掉的是接口层的浪费（格式错误、空等待、echo 代替检查），修不掉的是决策层的毛病（没做对却宣布完成、查出问题不去修）。
- **Q2（判官可信吗）：** 作为失败现象的分类器可用（宽松一致 97%），作为归责的分类器不可用（严格 κ 天花板约 0.6，复判一致率 77%）。可用的形态是双判官共识 + 人工兜底。
- **Q3（题目不清是真的吗）：** 部分是。接口约定类改题面立刻见效（extract-elf 0/6 → 3/3），领域知识类和环境工具类改题面没用。41 题里 7 道有可证实的缺陷。
- **Q4（训练能修残余吗）：** 在本项目的规模下没有。SFT（86 条自己的成功轨迹）和 RL（14 步 GRPO）在留出新题和 TB 上都与原版无差别；一次看似显著的 SFT 效果在重复评测里消失。harness × 训练的 2×2 交互项不显著，训练没有让模型摆脱对宽松解析的依赖。
- **Q5（提示怎么进训练）：** 实时 Teacher 比开头规则有效得多（25% vs 6%），能让全挂的难题产生学习信号；但提示留在上下文里训练，14 步后带提示的成功没有迁移到不带提示（撤掉提示后 72% → 8%，第 9 步 11 道题；跑完时 58% → 20%，5 道题）。提示依赖度这个指标虽然低（0.027），却没有预示迁移成功——它衡量的是"这条轨迹在不带提示时有多不可能"，不是"模型能不能自己走到这条轨迹"。

### 9.2 站得住的发现

1. 格式错误轮 −93%、跑满轮数上限的 trial 9 → 1：接口修补对弱模型的作用具体且可测。
2. "没做对却说做完了"换任何 harness 都在（23–31% 的失败）：归责到模型侧的依据是跨配置不变，而不是与强模型的差值。
3. `adaptive_wait`：空等待轮 −27%、token −11%、通过率不变；在 SWE-bench Verified 上用时 −32%；顺带发现上游死代码。
4. 任务质量审计：改题实验证实了判官的接口约定类标签；raman-fitting 和 dna-insert 展示了"题目不清"的三种不同形态。
5. 实时提示 vs 开头提示：25% vs 5–6%，两次独立实验方向一致。
6. 三次被数据推翻的乐观读数（契约子集效应、SFT 的假成功率、判官对措辞敏感），每次都是被同配置重跑或对照组推翻的。

### 9.3 方法论教训（按出现顺序）

1. 先测噪声底；噪声底本身也会被低估。
2. 对照臂与基线同时跑。
3. 子集效应要有事后独立批次复现；区间下界贴 0 不是证据。
4. 报告按"干预针对的子集 / 不针对的子集"分别给数，但拆得越细越容易拆出噪声，所以第 3 条更要执行。
5. 判官要给全 context、要测自身一致率、要有人工校准；细粒度归责标签只当筛选器。
6. 每个开关指向一个有计数的失败模式；没用的删。
7. 多臂比较不挑赢家。
8. 验证类干预的代价是时间不是 token。
9. 预注册的判据要先用已有数据核一遍能不能分辨；预测先做算术上限检查。
10. 分析脚本在拿到数据前写好并在旧数据上试跑。
11. 训练目标里算概率的方式必须与采样时一致（温度、截断、重复惩罚），否则梯度里有与奖励无关的偏置。
12. 基础设施：pkill 的模式不能和被匹配的文字写在同一条命令里；后台任务用完成标记；有副作用的命令不自动重试；多 job 并发前核对 Docker 网络数。

## 10. 局限与下一步

**局限。**
- 题目少（TB 30–41 道、留出合成题 37 道），单批的区间宽度 ±6–8 pp，只能分辨大效应。
- 合成题是单文件级的，对强模型有天花板（93–99%），与 TB 4 那种仓库级任务的分布有距离。
- SFT 只有 86 条样本、RL 只有 14 次更新，训练量比文献里小一到两个数量级；"没有提升"是在这个规模下的结论。
- RL 的训练目标前后不一致（第 1–3 步旧 log-prob）。
- 提示迁移的检验只在 51 道难题上做，试做每题每步只有 2 次。

**下一步（按信息量排序）。**
1. 不带提示的 RL 对照：只练 21 道"不带提示就有对有错"的题跑 5–6 步（约 25 美元），回答"这套 RL 流程在有信号的题上到底能不能推动模型"，把"提示迁移不了"和"RL 设置推不动"分开。
2. 若要继续用提示：按 HiLL 的做法惩罚高依赖的提示、把提示改短改成概念性的；或换 B 类做法（删提示 + 按 token 的概率修正）做对照。
3. harness 侧：只做不占模型轮次的干预——harness 在容器里执行检查并把结果塞回观察（对齐层 S4 的执行器版）；给模型看图的工具（chess 类题的失败全是像素启发式认子）。
4. 题目侧：仓库级合成任务；对 TB 2.1 的 7 道缺陷题提 issue。

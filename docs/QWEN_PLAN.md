## 0. 原则：先 harness，训练只管剩下的

harness 改动便宜、立刻生效、可撤回；训练要数据、GPU 和时间。所以顺序是：**先测出最好的 harness 能救回多少，把剩下的、且强模型在同一 harness 下不犯的，才算训练的责任。** 两侧的证据都来自同一批 TB 2.1 干净题（30 道），对照臂同时跑（D-040）。

- “跟模型有关吗”：同一个 Terminus 2 下，Qwen 的发生率比 gpt-6-sol / Seed 高多少（阶段 0 已测，见 `reports/stage0/patterns.md`）。
- “harness 能修多少”：同一个 Qwen，换 harness 配置后发生率和通过率变多少（本计划第 2 步）。
- 训练的目标 = 最好 harness 下仍然存在、且比 gpt-6-sol 高 ≥ 8 pp 的部分。

## 2. harness 侧：四个臂同时跑

TB 2.1 干净题 30 道 × 2 次，四个臂同时启动、各占四分之一并发，**Qwen 由我们自己租的 GPU 上的 vLLM 服务（bf16，同一份权重贯穿 harness 实验、rollout、训练前后评测）**，不再用 OpenRouter（阶段 0 只是没卡时的权宜之计：服务商精度不可控、Novita 返回空回复，D-052）；**所有臂都打开原始回复记录**（`trajectory_config.raw_content`），用来定格式错误的真实形态。H3 的 qwen-code 直接指向这个 vLLM（需开 `--enable-auto-tool-choice --tool-call-parser qwen3_coder`）。

| 臂 | 配置 | 回答什么 |
|---|---|---|
| H0 | Terminus 2 原样（同批重跑） | 同批基线 |
| H1 | H0 + 接口修补：宽松解析、接受交卷确认简写、开跑前环境探测、多行输入卡住提示。全部不占模型轮次 | harness 的“接口不合适”占多少 |
| H2 | H1 + 交卷把关（只在“宣布完成但没有运行证据”或“承认没做成”时打回一次） | harness 能把“假检查 / 假成功”压下多少、能不能转成通过 |
| H3 | Qwen 官方 harness（qwen-code，Harbor 自带，原生工具调用） | 给 Qwen 换一个为它设计的 harness 能到多少：接口适配的上限参考 |

预注册的预测：H1 解析失败轮数下降 ≥ 50%，通过率 +0 到 +5 pp；H2 在 H1 基础上假检查 + 假成功下降 ≥ 50%，通过率 +3 到 +10 pp；H3 不预测。判定照旧：Δ 按题配对 bootstrap，区间不含 0 且 ≥ 噪声底才算有效。

## 3. 归责表（第 2 步跑完后算）

每种毛病：H0 发生率 → 最好 harness 下的发生率 → harness 修掉的比例 → 残余；残余仍比 gpt-6-sol 高 ≥ 8 pp 的，交给训练。

**口径（2026-09-27 00:00 前后写定；此时第一批在跑，我只看过进度计数里各臂的通过数，样本太少不足以左右选择）：**“最好 harness”= H1 / H2 / H3 中两批合并通过率最高的臂（按点估计选；与 H0 的差是否显著单独报）；gpt-6-sol 的对照用阶段 0 它在同样 30 题上的 64 个 trial，按 `tools/qarm_report.py` 同一套规则重算（第 8 节）。附带发现：按这套规则 gpt-6-sol 也有 31% 的 trial 撞到 command not found，这一项不是 Qwen 特有的毛病（§1 表里“Seed 1%”来自另一套口径，不可比）。预期（待数据确认）：格式错误和环境类问题主要由 harness 解决；假成功 / 编造主要留给训练；假检查两边分担。

## 2–3 的结果（2026-09-27 02:12 美东，两批合并：每臂 30 题 × 4 次 = 120 trial；报告 `reports/qarm/summary.md`）

**通过率：三个改动都比 H0 高 5–6 pp，但没有一个显著。**

| 臂 | 通过率 | 与 H0 的按题配对差 | 95% 区间 | 判定 |
|---|---|---|---|---|
| H0 Terminus 原样 | 19/120（16%） | — | — | — |
| H1 接口修补 | 25/120（21%） | +5.0 pp | [−5.0, +16.7] | 不显著 |
| H2 H1 + 交卷把关 | 26/120（22%） | +5.8 pp | [−5.0, +17.5] | 不显著（H2 − H1 = +0.8 [−4.2, +6.7]） |
| H3 qwen-code | 26/120（22%） | +5.8 pp | [−3.3, +16.7] | 不显著 |

Qwen 自己的同配置噪声（第二批 − 第一批）：H0 −1.7、H1 −1.7、H2 +3.3、H3 −3.3 pp，都小于 8 pp，判定仍用 8 pp（D-057）。

**机制都量得清楚：**

| 毛病 | H0 | H1 | H2 | H3 | 读法 |
|---|---|---|---|---|---|
| 出现过格式错误的 trial | 57%（每 trial 2.6 轮） | 8%（0.17 轮） | 12%（0.87 轮） | 0% | 宽松解析在 H1 里实际救回 159 轮；原生工具调用没有这一层 |
| 跑满 100 轮上限 | 9 | 1 | 6 | 0 | 严格 JSON 下 Qwen 要么写坏 JSON，要么把代码拆成一行行追加、把轮数耗光（build-pmars 1/4 → H1 4/4，log-summary 0/4 → 3/4） |
| 命令不存在（全部 trial） | 40% | 38% | 32% | 17% | 环境探测没用：写明了没装，模型照样用；gpt-6-sol 同规则 31%，不是 Qwen 特有 |
| echo 代替检查（失败 trial） | 59% | 42% | 49% | 2% | 接口产物：Terminus 里模型只能借 echo “说话”；有了文字回复的出口就几乎消失 |
| 明知没做成仍宣布完成（失败 trial） | 30% | 31% | 29% | 23% | 所有 harness 下都在；把关也压不下去 → 模型侧 |

H2 的交卷把关打回 37/120 个 trial（没运行过 32、承认没做成 16），其中最后通过的只有 4 个（3 个是 git-leak-recovery）：能逼模型去查，但查出问题后修不好。阶段 0 三次全挂的 17 道：H0–H2 一道没翻，H3 各翻一次 path-tracing-reverse、cobol-modernization。

**预注册的预测：** H1“格式错误轮数降 ≥ 50%”成立（−93%），“通过率 +0 到 +5 pp”点估计 +5.0 落在区间内但不显著；H2“假检查 + 假成功在 H1 基础上降 ≥ 50%、通过率 +3 到 +10 pp”**证伪**（echo 42% → 49%，假成功 31% → 29%，通过率 +0.8）；H3 未做预测。

**归责（§3 的口径）：** 格式错误 → harness（换原生工具调用修掉 100%，宽松解析修掉约 90%）；echo 代替检查 → 接口产物，不是训练目标；命令不存在 → 不是 Qwen 特有；**明知没做成仍宣布完成（23–31% 的失败，任何 harness 下都在）和能力缺口（17 道里 15 道在任何 harness 下都不过）→ 模型侧，是训练的目标。** 两处口径问题如实记下：①“最好 harness”H2 与 H3 平票（都是 26/120），预注册规则没写平票怎么办，见 D-059；②“残余比 gpt-6-sol 高 ≥ 8 pp”这条规则在假成功上不可靠——gpt-6-sol 在阶段 0 只失败过 6 次，它的 17% 就是 1/6，所以上面“模型侧”的判断依据是“所有 harness 下都在、把关也压不下去”，而不是和 gpt 比的那 +12 pp。
其他：large-scale-text-editing 在四个臂里都出现过回复停不下来导致的超时（D-058）；基础设施故障 0。

## 4. 训练侧：只训残余，并且在最好的 harness 上训

- **目标**：第 3 步定出的残余毛病（预期以“假成功 / 编造 + 查出问题后不去修”为主）。
- **不蒸馏（硬规则，2026-09-26 用户定）：训练数据里的每个 token 都是 Qwen 自己生成的。** 别的模型只做四件事：出题、给提示（hint）、写评分细则（rubric）、判分。之前 Seed 采的 1256 条老师轨迹作废。
- **数据流程（实习那套：强模型给 hint、Qwen 自己 rollout、rubric 筛 Qwen 的成功轨迹）：**

```
合成题（gpt-6-sol 出题：针对残余毛病的题 + §4.5 的技能兄弟题）
   │
   ├─ Rubric Writer（gpt-6-sol，复用 agenteval/rubric：write_rubric → score_trial → validate_partial_order）
   │     每道题的过程细则，例如：交卷前真正运行了 <检查> 且看到通过；没有用 echo 打印成功代替检查；
   │     交付物里没有占位或编造的值；如实报告状态；每一轮动作格式合法
   │     细则须通过偏序检验：强模型的成功轨迹得分高于 Qwen 的失败轨迹（强模型轨迹只用来写细则，不进训练）
   │
   ├─ Qwen rollout × k（不给提示）
   ├─ 通过率太低的题：Qwen rollout × k（给提示）
   │     提示来自强模型，只有两种：行为提示（来自 bad pattern 分析，如“交卷前运行 X 并确认通过；不要写占位值”）
   │     和技能提示（读题面写出思路方向，不含答案）
   │
   ├─ 筛选：验证器通过 且 rubric 分数 ≥ 阈值 且 格式合法 且（给了提示的）轨迹里没有提到或复述提示
   │
   └─ 训练样本 = Qwen 自己的轨迹，给了提示的把提示从上下文里删掉（让模型学会“没人提醒也这么做”）
```

- **rollout 在哪跑：** 全部在我们自己 vLLM 上的同一份权重上采（包括过验证门），保证是对“要训练的那份权重”的采样；都在第 2 步选出的最好 harness 下跑，动作格式与部署一致。
- **训练：** LoRA SFT → 用训好的模型再采一轮、再筛、再训（expert iteration）；时间够再在合成题上做 GRPO（结果奖励 + rubric 奖励），完全 on-policy。
- **风险：** 删掉提示后，轨迹里的决策可能只在“有提示”时才说得通 → 筛选时由判官检查轨迹是否引用提示，引用的丢弃；在不给提示的留出题上评测，才算学会。
- **评测**：最好 harness + 训练后 vs 最好 harness + 原版；再做拐杖判定：训练后的模型还需不需要交卷把关（训练后 × H1 vs 训练后 × H2）。
- 最终得到一张 2×2（harness 修补 × 训练）：这就是“模型与 harness 共同进化”的实证。

## 4.1 训练阶段的具体方案（2026-09-27 09:10 美东定稿；用户 08:5x 确认“H2，按你说的来”；预注册，出题和采样之前写定）

**两个已定的决定：** 用 H2（Terminus + 接口修补 + 交卷把关）采 rollout（D-059）；评测以留出的合成题为主、TB 30 题为迁移检查（D-060）。

```
gpt-6-sol 出题（只给抽象技能描述）──▶ 构建 Harbor 题目 ──▶ 校验：参考解能过、什么都不做过不了、与 TB 89 题不像
      ──▶ 分成 训练 80 / 留出 40（按技能族分层）
训练题 × 3 次 Qwen rollout（H2，原版权重）──▶ 规则筛选 ──▶ LoRA SFT
留出 40 题 × 3 次、TB 30 题 × 4 次：原版 vs LoRA 同一个 vLLM、同时跑 ──▶ 按题配对比较
```

| 环节 | 具体做法 | 对应约束 |
|---|---|---|
| 出题 | gpt-6-sol，每题产出：题面、工作区文件、隐藏测试（pytest）、参考解（solve.sh）。6 个技能族：日志 / 文本用正则解析、数据格式转换（输出格式要求精确）、把小程序移植成 Python 且输入输出一致、实现一个本地小服务（HTTP / JSON）、git 仓库修复、SQLite 查询编写与优化。出题模型只拿到一句抽象的技能描述，看不到任何 TB 题 | 防污染 |
| 校验 | 参考解必须通过、什么都不做必须不通过；题面与 TB 2.1 全部 89 题做 5 词连续重合比对，过像即丢 | 防污染 |
| 采样 | 训练题 × 3 次，原版 Qwen、与四臂实验同一套 vLLM 配置、H2；开 `store_all_messages` + `raw_log` | 不蒸馏、前后一致 |
| 筛选（改动：规则代替 LLM 判官） | 验证器通过；没被把关打回；第一次宣布完成时，最后一次改文件后真的运行过东西；analysis / plan 里没有承认没做成的措辞；没发生上下文摘要；保留靠宽松解析修好的轮（部署用的就是 H2）。原计划用 agenteval 的 rubric 判官打分，改用规则的原因：这几条行为规则能精确判定、不花钱，而本项目测过判官之间 κ 只有 0.5–0.6 | 不蒸馏 |
| 训练 | LoRA，只加在注意力层（q/k/v/o），r = 16、α = 32、学习率 1e-4、2 个 epoch，只对 assistant 轮算 loss；先用 20 条样本测速度再定最大长度 | 预算 |
| 评测 | 同一个 vLLM 同时挂原版和 LoRA，两臂同时跑（D-040）；留出 40 题 × 3 次 × 2 臂，TB 30 题 × 4 次 × 2 臂 | 前后一致、统计口径 |

**出题结果（09:23）：** 150 道（gpt-6-sol，花费 9.72 美元，0 道解析失败）→ 合格 111 道（74%）：参考解过不了测试 37 道、初始化脚本在构建镜像时出错 2 道；与 TB 2.1 查重，最大重合只有 0.6% 的 5 词片段，一道没丢。各族合格数：数据转换 20、本地服务 22、日志解析 19、程序移植 17、SQLite 17、git 修复 16。划分训练 74 / 留出 37（计划 80 / 40；为省时间没有修那 37 道坏题）。

**预注册的指标与预测**（留出合成题为主；TB 为迁移检查）：
- M1 通过率：留出题 +5 到 +15 pp；TB 0 到 +5 pp（大概率不显著）。判定照旧：按题配对 bootstrap，区间不含 0 且 ≥ 8 pp。
- M2 第一次宣布完成时“最后一次改文件后没再运行过任何东西”的比例（即 H2 把关的触发条件）：相对下降 ≥ 30%。
- M3 失败 trial 里“明知没做成仍宣布完成”的比例（阶段 0 同一规则）：下降，不预测幅度。
- M2、M3 报点估计与按题 bootstrap 区间；三项都照报，不挑。

**消融（D-063，10:12 加，训练与评测之前）：** 两个 LoRA 超参相同——coderplain（只用普通采样的轨迹）与 coderlora（再加上带提示采样、删掉提示的轨迹）；留出合成题上原版 / coderplain / coderlora 三臂同时跑，TB 只跑原版与 coderlora。预测：coderlora 的 M2 低于 coderplain。另按 6 个技能族、按难度档（原版 3 次里过 0 / 1–2 / 3 次）拆开报通过率与差（描述性）。

**第三轮与共同进化 2×2（D-067、D-068，12:36–12:45 加，评测之前）：** 两轮都没做对的 51 道训练题，由 gpt-6-sol 逐题写技能提示（方法与易错点，不给代码和答案），Qwen 自己再做 3 次，删掉提示后并入训练 → 第三个 LoRA coderskill。评测九个 job 同时跑：留出题上 原版 / coderplain / coderlora / coderskill（都用 H2）+ 原版 × H0、coderskill × H0（凑成“harness × 训练”的 2×2）；TB 上 原版 / coderlora / coderskill（H2）。2×2 的看点：训练后补丁还有没有用（模型吸收了补丁的作用）、在 H2 下训练的模型回到原版 Terminus 会不会更容易出格式错误（模型适应了补丁）。

**预算与花钱前的检查：** GPU 已用约 46 美元（其中约 30 美元是昨夜空转），本阶段预计约 6 小时 ≈ 28 美元，累计约 74 美元，低于 100。API：只用于出题，上限 20 美元；先出 3 题试点，量出真实单价再定题数（gpt-6-sol 输入 2 美元、输出 10 美元每百万 token，思考过程按输出计）。更便宜的替代：用 TB 以外的现成题库做训练——但现成题库大多已被公开训练数据覆盖、也不针对这次的毛病，所以不用。可能出的问题：①HF 的 MoE 训练逐个专家循环、可能很慢 → 先测速；②合成题太易或太难 → 只有原版 3 次里至少过 1 次的题才提供训练样本，全过或全挂的题照样留作参考；③训练后格式变差 → 评测同时看格式错误率。

## 4.5 Qwen 三次全挂的 17 道题

阶段 0 里 Qwen 在 17 道干净题上 3 次全挂。它们大多不是“谁都做不出来”：同一个 Terminus 下 Seed 与 gpt-6-sol 多数能过（如 cobol-modernization、regex-log、sqlite-db-truncate、polyglot-c-py、llm-inference-batching-scheduler 都是 Seed 6/6、gpt 全过）；对谁都难的只有 gcode-to-text、query-optimize、path-tracing-reverse（Seed 0–2/6）；vulnerable-secret 上 gpt 0/3 是 OpenAI 内容审核拒答。所以这是 **Qwen 特有**的失败，分两类处理：

| 类 | 题 | 依据 | 怎么做 |
|---|---|---|---|
| A. 毛病拖垮的 | overfull-hbox、tune-mjcf、path-tracing-reverse（3 次都用 echo 代替检查）；mteb-retrieve、vulnerable-secret（3 次都“承认没做成仍宣布完成”，后者编造答案）；large-scale-text-editing、merge-diff-arc-agi-task（格式错误卡死）；llm-inference-batching-scheduler、sqlite-db-truncate | 规则标记在 3 次里反复出现 | 随第 2 步 harness 修补与第 4 步训练覆盖；第 2 步跑完先看有几道翻过来 |
| B. 技能缺口 | regex-log、kv-store-grpc、code-from-image、polyglot-c-py、cobol-modernization、gcode-to-text、query-optimize、chess-best-move | 规则标记少；两家判官多判“读错题 / 能力不够” | **同类技能的兄弟题**：换具体内容和场景、考同一种技能（按接口定义写 gRPC 服务、用正则解析日志、COBOL 翻 Python、给查询计时再优化……）。轨迹只用 Qwen 自己的 rollout；Qwen 做不出的题由强模型给技能提示，训练时删掉提示（§4） |

**防污染（硬规则）：** 这 17 道（以及整个 TB 2.1）只做评测，不进训练，也不造几乎一样的题。造兄弟题时提案模型只拿到一句抽象的技能描述，拿不到原题题面和参考解；造出的题与原题做相似度比对（n-gram 重合 + 判官判“是否同一道题”），过像即丢。训练后在这 17 道上翻过来的，才算真迁移。

**顺序：** 第 2 步 harness 四臂跑完后，把仍然三次全挂的题重新归类；B 类里残余 ≥ 2 道的技能簇才造兄弟题，按簇报告训练前后的翻转数。

# 实验日志：中途读数与转向理由

和 `HYPOTHESES.md`（预注册 + 终值）、`decisions.md`（设计决定）分工不同，这份只记两样东西：
1. **中途读数，以及它后来怎么变的** —— 哪些数字随样本增加而缩水、哪些结论被推翻；
2. **每次转向的理由链** —— 为什么下一步做的是这个而不是那个。

写它的原因：项目最终结论里最有价值的几条（契约的子集效应没有复现、判官在归责上不可靠、验证类干预的代价是时间）都不是一次实验得到的，而是"先得到一个乐观读数 → 加样或换角度 → 读数变化 → 改结论"的过程。只保留终值会把这条链抹掉。

---

## 第 0 阶段：立项与前置（2026-09-21 到 09-23）

- 选 Terminus 2 而不是 pi / DeepSeek Harness / FirstCoder：2.1k 行能全读懂，部件少，归因干净（D-001）。
- 先做三件"不做就是 toy"的事：测噪声底、预注册假设、准备强模型对照。这三件在后面每一次都救过场。
- 读上游源码时发现 `_execute_commands` 的 `except TimeoutError` 是死代码（非阻塞路径从不抛），成为后来 `adaptive_wait` 和 Harbor PR 的起点。

## 第 1 阶段：基线与噪声底（09-23）

| 时间 | 读数 | 后来怎么变 |
|---|---|---|
| E1 完成 | Seed lite 41 题 × k=3：trial 级 68.3%、pass@3 82.9%、19.1 元 | 保持，成为全项目参照 |
| E1n 噪声底 | 同配置两批 10 题 × k=5：60% vs 68% → **δ = 8 pp** | 09-25 复核时发现这是**低估**：同配置隔 3 小时能差 11.5 pp（D-040），噪声底后来改成一个分布（4 到 11 pp）而不是一个数 |
| E2 强模型 | gpt-6-sol k=1：92.7%，配对 +27.5 pp | 保持；但后来意识到它只剩 7.3 pp 空间，使"≥8 pp"的门槛在强模型上无法判定结构性 |

**转向 1：为什么先做判官而不是直接改 harness。** E1 的规则标签说 64% 的失败是"没验证就说完成"，但这个标签太粗——它既可能是"理解错了题"也可能是"做对了没查"。判官把它拆成题意误读 36% / 验证不足 21% / 题目不清 8%，这个拆分直接决定了第一圈做哪三个开关。

## 第 2 阶段：第一圈 harness（09-23 到 09-24）

按判官分布选了三个：任务契约（对题意误读）、完成前把关（对验证不足）、自适应等待（对空等待）。另加卡死提醒、预算提示、退出码提示三个"顺手"的——**这三个没有 bp 支撑，后来全部退役**（D-039），教训写进 D-038：每个开关必须指向一个有计数的失败模式。

| 中途读数 | 当时的解读 | 最终 |
|---|---|---|
| 契约 26 题：**+7.7 pp**，模糊题子集 **+13.9** | "方向证实，收益集中在模糊题" | 补跑到每题 6 次后缩到 **+6.7 [−5.2, +21.4]**，且几乎全由 extract-elf 一道题贡献（D-036）；再到 E4p 才看清是 **+7.6 模糊题 / −7.4 清晰题**（D-048） |
| adaptive-wait 73/78 时 61.6% | "通过率基本不变" | 补跑 5 条后 **59.0%**（D-033）；结论不变但数字要以 78/78 为准 |
| auditor：打回 22 次、判官看都"对" | "独立审计有效，只是慢" | **+0.0 pp、成本 +29%、超时 10→17**；"知道没做完"和"能做完"之间有差距，弱模型填不上 → 退役 |
| self_check +6.4 | "比 auditor 好" | 强模型上 −2 pp、成本 +79% → 拐杖 |

**转向 2：为什么去验证判官而不是继续改 harness。** 五个改动没有一个越过 δ。两种可能：改动没用，或者靶子选错了。靶子来自判官，所以先查判官。

## 第 3 阶段：判官可靠性（09-24 到 09-25）

这一段的每个数字都被后一个实验修正过，完整链条：

| 步骤 | 读数 | 引出的下一步 |
|---|---|---|
| 两家判官互相 | κ **0.49**（预注册要 0.80） | 证伪。但分歧集中在三个相邻标签之间 → 加"宽松口径"（算次标签）得 79.5% |
| 措辞不变性（M3） | 改写自述后翻转 **27% / 30%** | 看似"判官只看措辞"→ 但**对照组**（原文重判）也翻 **23%**！真正的发现是判官自身复判一致率只有 77%（D-035） |
| 人工仲裁 13 条难例 | 判官 vs 人 κ **0.30** | 发现系统性偏差：8 条"题面缺信息"判官只判对 2 条；还有两条 overfull-hbox 判官**编造了证据**（指控的不合法同义词经重放核对全在表里，真正违规的是介词 in→at） |
| 给全 context（隐藏测试 + 参考解 + 完整验证器输出） | κ 0.30 → **0.40** | 证明"半盲"设计是错的（D-037），但仍有系统性偏差 |
| 加五条人工判定规则（v3） | κ → **0.63**（样本内） | 样本外 15 条只有 0.57，与旧判官持平 → 规则消掉的是系统性错误，不是提高了天花板 |
| 换更强模型 gpt-6-astra | κ **0.55**，宽松 87%，不如 sol 三票 | 瓶颈不在模型档位（D-045），10 美元买了一句确定的话 |
| 两家 v3 共识 | 一致 56%，一致时对人工 **86%** | 最终设计：共识采信、分歧送人工（D-044） |

**转向 3：为什么做第二圈而不是继续调判官。** 人工仲裁把 bad pattern 修正了：题面缺信息 8（harness 改不了）、验证不足 8、无交付超时 7。第一圈的靶子（题意误读 36%）大部分其实是题面缺信息——**契约对着一个多半不存在的靶子打**。第二圈按修正后的 bp 选了两个：交付检查点、验收式自测。

## 第 4 阶段：改题实验（09-24）

用来回答"判官说的题目不清是不是真的"：

| 题 | 改题前 | 改题后 | 读法 |
|---|---|---|---|
| extract-elf | 0/6 | **3/3** | 题面示例地址与参考实现自相矛盾，是真缺陷 |
| cancel-async | 2/6 | 3/3 | 同上 |
| raman-fitting | 0/6 | 0/3 → E8b 补到底仍 0/3 | 缺的是领域知识（1e7/x 换算），改题面救不了 |
| dna-insert | 1/6 | 0/3 → E8b 3/3 | 边界约定 + oligotm 版本，题 + 环境 |
| path-tracing（对照，不改） | 0/6 | 0/3 | 如预期不变 |

→ D-034：判官的"题目不清"要拆成接口约定 / 领域知识 / 环境工具三类，只有第一类改题就好。这条后来回灌成契约 v2 的七类清单（D-042），是审计 → harness 的第一次回流。

## 第 5 阶段：第二圈（09-25 到 09-26）

| 中途读数 | 当时判断 | 最终 |
|---|---|---|
| 46/78 时验收式自测超时 19（基线 9） | "和审计门同一种病" | 78/78 时**超时 34、轮数 15.9→43.3、成本 +110%、通过率 −6.4** —— 判断正确且更严重 |
| 交付检查点：无交付 11 → 6，触发 51 次 | "机制成立" | 保持；但通过率 **−5.1**，成本反降 17%。"先写个答案"让文件存在了，写进去的多半是错的 |

→ **D-047 的核心教训：在有硬时限的 benchmark 上，任何让模型多走一轮的提示类干预都自带负项。** 往后只做不占模型轮次的干预。

同期 H14（离线 best-of-3 选择）：按预注册规则选中 **50.0%**，比随机选（61.5%）还差 —— 模型自述不能当选择信号。

## 第 6 阶段：E4p 与“条件式发现”（09-26，已被第 7 阶段推翻）

原意是给契约加样到每题 6 次看能否越过噪声底。结果全集仍是 ±0，但**第一次按子集拆开**：

- 模糊题 14 道：61.9% → v1 69.0% / v2 71.4%
- 清晰题 27 道：84.0% → v1 76.5% / v2 79.0%

**两个方向抵消**，这才是前面所有"全集看不出效果"的原因（D-048）。合并三批后模糊题 Δ **+7.6 [−0.0, +17.2]**，下界正好压零。

v2（你提的 infer 版）的意外发现：账本命中决定性细节 v1、v2 都是 80%，但**命中之后的通过率 v1 是 8/12、v2 只有 3/12** —— 强制逐点写 resolutions 让模型在已经想对的地方改主意。识别和决策是两回事。

→ H17：条件式契约，只在模型首轮列出决定性模糊点时启用。这是第一个有明确理由预期为正的改动。

## 第 7 阶段：H17，开关成功、前提失败（09-26）

**开跑前的两次修正（都是看数据前做的）：**

| 发现 | 依据 | 改动 |
|---|---|---|
| 预注册的开关没有区分力 | 翻已有数据：契约 v1 首轮在清晰题上 78/81 = 96% 都列了模糊点 | 离线预检三种开关（首轮只依赖题面，不用起容器，约 3.6 元）：首轮自评 79% / 43%，开跑前单独评分 90% / 27%，采用后者（D-049）；关掉思考能从 44 s 降到 3 s，但误开率翻倍到 57%，所以不关 |
| 预注册的全集预测在算术上不可达 | 全集 Δ = 模糊占比 × 模糊 Δ + 清晰占比 × 清晰 Δ；开关完美时上限也只有 14/41 × 7.6 ≈ +2.6 | 撤回“全集 +2 到 +6”，改为按子集判定：清晰题 ≥ −3 且模糊题 ≥ +5 |

另外开跑前把分析脚本写死（`tools/h17_report.py`），并在 E4p 数据上试跑复现了 −2.4 / +7.1 / −7.4。

**中途读数：** 评分开关的清晰题误开率从 3/7 → 4/10（40%，超门槛）→ 5/16 → 12/32 → 终值 24/81（30%）。又一次“早期小样本读数偏离、最后回到预检值”。

**结果：** 开关本身完全按设计工作（86% / 30%，评分中位 48 s，只超时 1 次），但模糊题 −4.8、清晰题 +2.5、全集 +0.0，预注册判定不成立。

**关键的一步是把 H17 当作契约的第四批来复查**，而不只是报“H17 不成立”：

| 读数 | 模糊题 | 清晰题 |
|---|---|---|
| E4 → E4t → E4p → H17 | +13.9 → +4.8 → +7.1 → −4.8 | +2.4 → — → −7.4 → +3.7（被误开的 9 道） |
| 合并 | 三批 +7.9 [+0.0, +17.5] → 四批 **+4.8 [−3.0, +13.1]** | E4+E4p −4.9 [−13.0, +2.5] |

D-048 的“两个方向对称抵消”来自一个批次，下一批两个方向都没有复现。→ D-050 撤回 D-048：契约在任何粒度上都没有可复现的效果。

**事后看，第 6 阶段有三个该警觉的信号：** 子集是在 E4 看到 +13.9 之后才被当成重点的；两个方向恰好对称、各有一个机制故事，太干净；合并区间下界正好是 0。H17 的价值在于它是**在提出效应之后才跑、判定口径预先写死**的独立批次，所以结果没有解释空间。

## 贯穿全程的方法论教训（按出现顺序）

1. 先测噪声底再谈效果（D-013）；噪声底本身也会被低估，要用多对同配置批次估成分布（D-040）。
2. 对照臂必须与基线**同时并行**跑，顺序跑会吃到批次漂移。
3. 子集效应在写进结论前必须补跑到每题 ≥6 次（D-036），**且要有一个在提出该效应之后才跑、判定口径预先写死的独立批次复现**；合并区间下界贴 0 不算证据（D-050）。
4. 报告必须按"干预针对的子集 / 不针对的子集"分别给数，否则条件式手段会被误判为无效（D-048 的方法论部分，保留）；但按子集拆开也更容易拆出噪声，所以第 3 条的复现要求更要执行。
5. 判官要给全 context，要测它自己的复判一致率，要有人工校准；细粒度归责标签只能当筛选器（D-035、D-037、D-044）。
6. 每个 harness 开关必须指向一个有计数的失败模式，没有就别加（D-038）；没用的要删（D-039）。
7. 多臂比较不挑赢家，所有臂一起报（D-046）。
8. 验证类干预的真实代价是**时间**不是 token（D-047）。
9. 预注册的判据要先用已有数据核一遍能不能分辨（H17 的首轮自评开关在清晰题上 96% 都会开），预测要先做算术上限检查（全集 +2 到 +6 不可达）；两样都能在花钱前发现（D-049）。
10. 分析脚本在拿到数据前写好并在旧数据上试跑，跑完只执行不改口径（`tools/h17_report.py`）。
